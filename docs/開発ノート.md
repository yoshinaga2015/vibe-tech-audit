## 2026-08-18 — README 体裁刷新（EN / JA）

### 変更の具体

- `README.md` / `README.ja.md` 先頭に Docs EN/JP 切替バッジを追加（表示中言語を強調色）
- 中央寄せヒーロー（タグライン・姿勢・バッジ列・ページ内ナビ）
- Modes / adversarial / 否定リストを表と固定幅フローで整理
- リポジトリ構成図のルート表記を `publish/` から `.` に修正（GitHub ルートと一致）

### 意図

GitHub ランディングとして、言語切替とスキルの価値提案を一瞬で伝え、中身の契約（証拠必須・報告ファースト・fix は明示時のみ）を視覚的に固定する。

### ADR

- **Decision:** README の視覚言語は slate + sky の shields バッジに統一し、言語切替は右上 for-the-badge、メタ情報は flat-square とする。
- **Why:** セキュリティ系ツールの「暗い・実務的」トーンを保ちつつ、言語切替を見落とさないコントラストを取る。
- **Rejected:** 絵文字だらけのヒーロー、紫グラデ系テンプレ、本文冒頭のプレーン「日本語 README」リンクのみ（重複・弱い）。
- **Consequence:** shields.io 依存（オフライン表示時はバッジ画像が欠けるが、リンク文言は残る）。

## 2026-08-18 — インストールを `npx skills` に移行

### 変更の具体

- README（EN/JA）の主インストール経路を `npx skills add yoshinaga2015/vibe-tech-audit` に変更
- `-s` で EN/JA を選択、`-a cursor`、`-g` で個人スコープ／省略でプロジェクトスコープ
- `skills.sh` インストール数バッジを追加
- `cp` 手順は `<details>` の手動フォールバックに降格
- `npx skills add … -l` で両 Skill が検出されることを実機確認済み

### 意図

Agent Skills の標準配布経路に合わせ、クローン＋コピーより短い一次導線にする。更新は `npx skills update`。

### ADR

- **Decision:** 一次インストールは Vercel Labs の skills CLI（`npx skills`）とする。独自 npm ラッパーは作らない。
- **Why:** GitHub がレジストリ。既に `skills/` 配下に 2 Skill があり CLI が発見できる。独自 CLI はメンテコストだけ増える。
- **Rejected:** リポジトリ直下に単一 `SKILL.md` へ統合（日英分離を壊す）、独自 `npx vibe-tech-audit` パッケージ。
- **Consequence:** Node/npm が必要。オフラインや npm 不可環境は手動 `cp` フォールバックを維持。

## 2026-08-18 — skills.sh インストール数バッジを撤回

### 変更の具体

- `https://skills.sh/b/yoshinaga2015/vibe-tech-audit` は SVG 上で `custom badge: resource not found` を返すため README から削除
- 代替として shields.io の静的 `install · npx skills` バッジ（アンカーへリンク）を配置
- GitHub リポジトリに topic `agent-skills` / `cursor` / `security` と description を設定（発見性・将来のインデックス用）

### 意図

壊れた画像を出さない。CLI インストール自体は既に動く（`npx skills add … -l` で 2 Skill 検出済み）。

### ADR

- **Decision:** skills.sh の動的インストール数バッジは、テレメトリにソースが載るまで使わない。
- **Why:** バッジは docs に書いてある形式でも、未インデックス／未集計リポジトリでは not-found SVG になる既知挙動。README の欠落ファイルが原因ではない。
- **Rejected:** 壊れたバッジを残して「そのうち直る」待ち。
- **Consequence:** インストール数が増えて skills.sh ページが生きたら、その時点で公式バッジを再追加してよい。

## 2026-08-18 — README バッジをスリム化

### 変更の具体

- ヒーローから削除: `install` / `skill EN|JA` / `modes` / `lens` の静的バッジ
- 残すもの: License（MIT）＋右上 EN/JP 言語切替（`Docs` label を外して EN/JP のみ）
- 機能・導線はテキストナビと本文表に一本化
- ヒーロー副題（`Cursor Agent Skill · 証拠必須 · …`）を削除（タイトル＋一行説明で足りる）
- インストール主経路を `npx skills add` に変更（`cp` は details フォールバック）

### 意図

バッジを「検証可能なメタデータ」に限定し、機能カタログのバッジ化アンチパターンをやめる。vercel-labs / anthropics の Skill リポ慣例（必要最小限）に寄せる。

### ADR

- **Decision:** 上部バッジは License のみ。skills.sh 動的インストール数はインデックス後に追加可。
- **Why:** Modes/Lens/Skill 名は本文で説明すべき契約であり、ステータス徽章ではない。
- **Rejected:** 機能を並べた装飾バッジ列、静的 `npx skills` 宣伝バッジの併用。
- **Consequence:** ヒーローは視覚的に静かになる。発見導線は Install 節とテキストナビが担う。

## 2026-08-18 — マルチエージェント対応（Cursor / Claude Code / Codex）

### 変更の具体

- README の既定インストールを `-a cursor -a claude-code -a codex` に変更（単体・`*`・手動パス表も追加）
- Requirements を「Agent Skills 対応ホスト」中心に書き換え
- Skill 内の Cursor 固有語 `AskQuestion` をホスト非依存の「ユーザーに1回確認」に置換（EN/JA・fix-findings）

### 意図

本体はもともと Agent Skills（`SKILL.md`）形式でホスト非依存。不足していたのは「Cursor 専用に見えるインストール導線」と Cursor 専用ツール名だった。

### ADR

- **Decision:** 配布の一次ターゲットを Cursor + Claude Code + Codex の3つとする。全ホストは `-a '*'` で明示。
- **Why:** skills CLI がディレクトリ配置を担当する。独自ラッパーやホスト別 SKILL 分岐は不要。
- **Rejected:** Claude 用・Codex 用に Skill フォルダを複製する案（ドリフトの温床）。
- **Consequence:** プロジェクトスコープでは Cursor/Codex が `.agents/skills/`、Claude Code が `.claude/skills/` になる点を README 表で明示する。個人 Cursor skill への自動同期は本コミットでは行わない（必要なら `npx skills add … -a cursor -g` で入れ直す）。

## 2026-08-18 — インストール主経路を対話形に短縮

### 変更の具体

- README の第一例を `npx skills add yoshinaga2015/vibe-tech-audit` のみに変更
- `-s` / `-a` / `-g` / `-y` 付きの長いコマンドは `<details>非対話 / CI</details>` へ移動

### 意図

skills CLI の定石（対話で Skill・エージェント・スコープを選ぶ）に合わせ、人間向け README を短くする。

### ADR

- **Decision:** 人間向けは最短対話形。長いフラグ列は CI / スクリプト専用。
- **Why:** vercel-labs/skills の第一例も `owner/repo` のみ。長い形は非対話向け。
- **Rejected:** 主要3エージェントを毎回 README 先頭で全部指定する案。
- **Consequence:** 初見ユーザーはプロンプトに従う。自動化利用者は details を開く。

## 2026-08-18 — README の AI 臭い文体を削減

### 変更の具体

- 文末コロン導入（「潰します:」「で:」「マッピングしています:」）を句点・通常文に置換
- 婉曲な免責（「〜ようには表現しません」）を「代替ではない」へ直截化
- 「薄い SKILL.md」「progressive disclosure」「既定の姿勢:」など文学・ラベル調を平易な説明に変更
- 「これは何ではないか」→「対象外」など見出しも実務調に
- adversarial-review 冒頭の同種表現も合わせた

### 意図

公開ドキュメントの信頼度を上げる。機械翻訳・生成文にありがちな indirection を落とす。

### ADR

- **Decision:** ユーザー向け prose（README EN/JA）を優先して直す。チェックリスト本体の「確認:」列は表形式の作業メモなので今回は触らない。
- **Why:** ユーザー指摘のパターンはランディング文に集中していた。
- **Rejected:** 全 references の「行動:」ラベル一括削除（ワークフロー可読性が落ちる）。
- **Consequence:** 以後の README 編集も同基準（コロン導入・過剰婉曲・薄い/厚い比喩を避ける）。
